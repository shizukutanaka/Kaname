# BEC スコアリング — 言語非依存仕様

バージョン: 1.0 | 作成日: 2026-05-26

---

## 1. 概要

BEC (Business Email Compromise) スコアリングは複数の信号を組み合わせて
0.0〜1.0 のリスクスコアを計算する。

(初版は 7 信号の設計だったが、認証系 (SPF/DKIM/DMARC/ARC)・AiTM・
スレッド乗っ取り・送信者文体認証等が追加され、現在は ~14 経路。
信号の正確な一覧は `crates/kaname-bec/src/lib.rs` の `signals.push` が
正規のソースである)

---

## 2. スコア閾値

| スコア | カテゴリ | UI 表現 |
|---|---|---|
| 0.0 以上 0.3 未満 | Safe | 何も表示しない |
| 0.3 以上 0.6 未満 | Advisory | 黄色の注意バナー |
| 0.6 以上 0.85 未満 | Suspicious | オレンジの警告バナー |
| 0.85 以上 1.0 以下 | Dangerous | 赤い危険バナー + 送信ブロック推奨 |

(実装 `Thresholds::default()`: advisory=0.30, suspicious=0.60, dangerous=0.85。
初版の 0.5/0.7 から引き上げ済み — 過剰な警告疲れを抑えるため)

---

## 3. 信号一覧 (初版 7 信号 + 後続拡張)

以下は初版で定義した 7 信号。その後認証系・AiTM・スレッド文脈等が追加されている。

### 信号 1: ドメインタイポスクワット (Levenshtein 距離)
- 既知の正規ドメインからの編集距離が 1〜3 の場合
- 完全一致は除く (正規ドメインと一致する場合は 0 点)
- スコア加算: +0.40

### 信号 2: 緊急性マーカー
- 「至急」「緊急」「本日中」「urgent」「immediately」等
- スコア加算: +0.15 (マーカーごと、最大 0.30)

### 信号 3: 振込パターン
- 「振込」「口座変更」「wire transfer」「payment change」等
- スコア加算: +0.30

### 信号 4: 送信時刻異常
- 深夜 22:00〜翌 5:00 の送信
- 土日祝日の緊急依頼
- スコア加算: +0.15

### 信号 5: QR コードフィッシング
- 添付画像内の QR コードから疑わしい URL が検出された場合
- スコア加算: +0.25

### 信号 6: VEC パターン
- 既知取引先ドメインの Levenshtein 距離 1 偽装
- スコア加算: +0.45

### 信号 7: メール爆撃
- 同一送信者から短時間に大量メール
- スコア加算: +0.20

### 最終スコア計算
信号の寄与を合算した raw をロジスティック変換して 0.0〜1.0 に写像する:
```
raw   = sum(signal.contribution)
score = logistic((raw - 0.7) * 5.0)   // clamp(0,1)
```
線形加算クリップは独立シグナルの重複カウントで過大評価を生むため採用しない。
(k=5, bias=0.7 で raw=0 → ≈0、raw=1 → ≈0.95 に調整済み。

なお「悪い信号を追加するとスコアは低下しない (単調増加)」の不変条件は
ロジスティック変換でも保持される (単調増加関数の合成)。

---

## 4. 不変条件

- スコアは常に 0.0 以上 1.0 以下
- 同一入力からの計算は常に同じスコアを返す (決定論的)
- 悪い信号を追加するとスコアは低下しない (単調増加)
- 空のメールはスコア 0.0
