# skill: review

コードレビューを実施する。Kaname のセキュリティ原則に基づいて評価。

## 発火条件
- 「レビューして」「review」「確認して」「チェックして」

## レビュー手順

### 1. セキュリティファースト
- [ ] `Content<Untrusted>` の取り扱いが正しいか
- [ ] `unwrap()` が本番コードに存在しないか
- [ ] PII がログに含まれていないか
- [ ] 新しい依存が `deny.toml` の許可リストに合うか

### 2. 型安全性
- [ ] Phantom Type の境界が維持されているか
- [ ] `#[deny(unsafe_code)]` を壊していないか

### 3. テスト品質
- [ ] 新機能にテスト ≥ 5 件あるか
- [ ] 攻撃ケースのテストがあるか (AiTM, BEC, etc.)

### 4. ドキュメント
- [ ] `//!` または `///` コメントが追加されているか
- [ ] CHANGELOG.md が更新されているか

## 出力フォーマット
```
## レビュー結果

### ✅ 良い点
- ...

### ⚠️ 要確認
- ...

### ❌ 修正必須
- ...

### 総合評価: APPROVE / REQUEST_CHANGES
```

## Gotchas
- `unsafe` ブロックは原則 REJECT
- test 内の `unwrap()` は許可
